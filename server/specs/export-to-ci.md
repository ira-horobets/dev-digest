# Export to CI (SPEC-05) — server

Spec: specs/export-to-ci.md (SPEC-05)

Generates a CI bundle for one agent, opens a pull request on `devdigest/ci` in
a GitHub repo, tracks the installations, and pulls the results of the workflow
runs back from the GitHub API. This file owns the routes, the data model, the
generated files, the ingest rules and the invariants. The UI half lives in
[`client/specs/export-to-ci.md`](../../client/specs/export-to-ci.md); the
runner that executes in CI is described in
[`agent-runner/README.md`](../../agent-runner/README.md); flows and decisions
are in [`../docs/export-to-ci.md`](../docs/export-to-ci.md).

Status: **implemented 2026-11-01**. One migration, `0018_fantastic_gideon.sql`.

## Module

`server/src/modules/ci/`: `routes.ts` (plugin) · `service.ts` (`CiService`:
preview, secrets, export, update, installations) · `ingest.ts`
(`CiRunsService`: list, refresh) · `generate.ts` (pure file builders) ·
`helpers.ts` · `repository.ts` · `ports.ts` · `constants.ts`. The module
imports no other module and not `@devdigest/reviewer-core`; it makes no model
call. The repository comes from the container getter `ciRepo`
(`platform/container.ts`); the runner bundle from `platform/runner-bundle.ts`.

## API (`modules/ci/routes.ts`)

| Route | Body / query | Result |
|---|---|---|
| `POST /agents/:id/ci/preview` | `CiPreviewInput { repo, post_as, triggers }` | `CiPreview { files, template_version, memory { included, total, dropped }, repo_public, workflow_state, studio_token }`. Reads GitHub only for the workflow state and repo visibility, bounded by 1.5 s (`PREVIEW_GITHUB_TIMEOUT_MS`); on timeout, error or no token `workflow_state` is `unknown` |
| `GET /agents/:id/ci/secrets?repo=` | `repo` required | `CiSecretsView { secrets: CiSecretStatus[], studio_token }` |
| `POST /agents/:id/export-ci` | `CiExportInput { repo, target='gha', action='open_pr', post_as, triggers, workflow?, confirm_overwrite, confirm_secret_warning }`, body limit 128 KB, 10/min | `CiExport { installation, files, pr_url }` |
| `GET /agents/:id/ci/installations` | — | `CiInstallationsView { installations, active_count }` |
| `POST /agents/:id/ci/installations/:installationId/update` | — | `CiUpdateResult { installation, pr_url, error }`, 10/min |
| `GET /ci/runs` | `CiRunsQuery { range=7d (24h·7d·30d), agent_id?, repo?, status? }` | `{ runs: CiRun[] }`, stored rows only, newest first, limit 200 |
| `POST /ci/runs/refresh` | — | `CiRunsRefreshResult { ingested, running, retry_at, errors[] }`, 12/min |

No route accepts a result body. `PUT /agents/:id` (agents module, the `useUpdateAgent` call) is
reused unchanged for "Fail CI on".

Errors: provider other than `openrouter` → 422; repo not `owner/name` → 422;
repo not imported → 404; invalid YAML in `workflow` → 422; key-like text in
`workflow` without `confirm_secret_warning` → 422 (`code: secret_in_workflow`);
a foreign workflow at the target path without `confirm_overwrite` → 409; no
`GITHUB_TOKEN` → `ConfigError`; a GitHub rejection → `ExternalServiceError`
with `details { status, missing_permission }`.

## Generated files (`generate.ts`)

Order and editability, as `buildFiles` returns them:

| Path | Content | Editable |
|---|---|---|
| `.devdigest/agents/<slug>.yaml` | exactly the seven `AgentManifest` fields (`name`, `provider`, `model`, `system_prompt`, `skills`, `strategy`, `ci_fail_on`) | no |
| `.devdigest/skills/<skill-slug>.md` | one per enabled link to an enabled skill, link order; the raw skill body, no frontmatter | no |
| `.devdigest/memory.jsonl` | `{id, scope, kind, content}` lines, newest first, at most 200 lines and 100 KB; empty file when no row qualifies | no |
| `.devdigest/runner/index.js` | the committed bundle `agent-runner/dist/index.js` | no |
| `.github/workflows/devdigest-review.yml` | header `# devdigest-ci/v1 · generated by DevDigest · editable`; `on.pull_request.types` = chosen triggers; `permissions` `contents: read` and `pull-requests: write` (`github_review`, `pr_comment`) or `read` (`none`); `concurrency` `devdigest-review-${{ github.event.pull_request.number }}` with `cancel-in-progress`; `ubuntu-latest`, `actions/checkout@v4`, `actions/setup-node@v4` (Node 22), `node .devdigest/runner/index.js` with `OPENROUTER_API_KEY`, `GITHUB_TOKEN`, `DEVDIGEST_AGENT`, `DEVDIGEST_POST_AS`; `actions/upload-artifact@v4` (`if: always()`, `devdigest-result`, file `devdigest-result.json`) | yes |

Slugs: `slugify(name)` (a module-local copy of the skills algorithm) with `-2`,
`-3` suffixes on collision. Memory rows: scope `global`, or scope `repo` for the
selected repo; embeddings are never selected. Rows whose content
`looksLikeSecret` are dropped before the caps and counted in `memory.dropped`;
`memory.total` counts the rows that may be exported. Prompt, skills and memory
are written through the YAML and JSON serializers, never concatenated.

## Data model

Relations: `ci_installations.agent_id` → `agents` (cascade);
`ci_installation_events.installation_id` → `ci_installations` (cascade);
`ci_runs.ci_installation_id` → `ci_installations` (set null);
`ci_runs.agent_run_id` → `agent_runs` (set null). The ER diagram is in
[`../docs/export-to-ci.md`](../docs/export-to-ci.md).

| Table | Role |
|---|---|
| `ci_installations` | one per agent + repo + `target_type` (unique `ci_installations_agent_repo_target_uidx`): `branch`, `pr_url`, `pr_number`, `pr_state` (`open·merged·closed`), `pr_state_checked_at`, `workflow_version`, `config_hash`, `post_as`, `triggers` (jsonb) |
| `ci_installation_events` | one per install or update attempt: `action`, `at`, `template_version`, `config_hash`, `outcome` (`succeeded·failed`), `pr_url`, `error`; index on `(installation_id, at)` |
| `ci_runs` | one per ingested GitHub run attempt: `github_run_id`, `run_attempt`, `pr_number`, `ran_at`, `status`, `verdict`, `findings_count`, `blockers`, `cost_usd`, `duration_ms`, `github_url`, `error`, `agent_run_id`; unique `ci_runs_inst_run_attempt_uidx (ci_installation_id, github_run_id, run_attempt)` |
| `agent_runs` (existing) | one linked row per ingested run: `source='ci'`, `kind='review'`, `pr_id` null, status `done` or `failed`, never `running` |

`ci_installations` and `ci_runs` have no `workspace_id`. Every repository query
joins `agents.workspace_id` through the installation's agent. A `ci_runs` row
whose installation was deleted has a null installation id and is not listed.

## Behaviour

Export (`CiService.exportCi`): requires the studio token; refuses a non-OpenRouter
provider; regenerates the files server-side; swaps in `workflow` when given;
reads the live default branch (`getRepoInfo`) and the existing workflow; makes
exactly one `commitFiles` to `devdigest/ci` from that default branch; reuses
the open PR from `devdigest/ci` (`findOpenPr`) or opens "Add DevDigest CI
review"; on a 422 from `openPullRequest` it looks the PR up again. On success
it upserts the installation and records an `install` event. A failed first
export records nothing; a failed export of an existing installation records a
`failed` event.

Update (`CiService.update`): regenerates every file, including the workflow, from
the stored `post_as` and `triggers`, so edits to the workflow in `devdigest/ci`
are overwritten. Same commit and PR path with the title "Update DevDigest CI
config". It returns `error` instead of throwing when GitHub rejects; the event
is recorded `failed`.

Installations (`CiService.installations`): `out_of_date` is true when the stored
`workflow_version` differs from `CI_TEMPLATE_VERSION` or the stored
`config_hash` differs from the hash of a fresh regeneration (sha256 over the
non-editable files and the template version, so a change to `ci_fail_on`, the
prompt, a skill body, memory or the runner bundle marks it). PR state is read
per installation with `getPullState`; on failure the stored state is returned
with `pr_state_stale: true`. `active_count` counts merged PRs.

Secrets (`CiService.secrets`): `GITHUB_TOKEN` is always `ready`.
`OPENROUTER_API_KEY` is `ready` when listed in the repo or organization
secrets; `not_set` only when both lists were read and it is absent and the
repo has no environments; `unknown` with a reason otherwise (no studio token,
403/404, rate limit, network, unreadable organization list, environments).

Ingest (`CiRunsService.refresh`): per `gha` installation it lists up to 50
runs of `devdigest-review.yml`. Not-completed runs come back as transient
`running` rows in `running`, never stored. Each completed run not yet stored
downloads the artifact `devdigest-result` (size checked before download), parses
it and inserts one `agent_runs` and one `ci_runs` row in one transaction. A
rate-limit error stops all further calls, sets an in-memory `blockedUntil` per
workspace and returns `retry_at`; `refresh` makes no GitHub call until then.
Other per-repo errors go to `errors[]` and the loop continues. `list` never
calls GitHub.

CI run status: `failed` when the job did not succeed or the artifact is
missing, oversize or invalid; `no_findings` when it succeeded with zero
findings; `succeeded` when it succeeded with findings. A valid artifact makes
`agent_runs.status = done` even when the job failed on the gate. The job URL
comes from the GitHub API, not the artifact. Run `ran_at` is the run's
`created_at`; `ci_runs.duration_ms` is `updated_at − run_started_at`; the PR
number is the first PR of the run, else the artifact's.

Error mapping (`helpers.ts mapGitHubError`): fine-grained tokens name the
permission from `x-accepted-github-permissions`; classic tokens name the scope
from accepted minus granted OAuth scopes; otherwise `PERMISSION_TABLE` per
operation. A bare 404 never names a permission.

## Invariants

1. Every commit goes to `devdigest/ci`; nothing is written to the default branch (`CI_BRANCH`, `CiService.pushToCiBranch`).
2. The GitHub token is read only by `SecretsProvider` through `container.github()`; services see `deps.github()` and never the value. It is absent from responses, mapped errors and generated files (`ci-service.test.ts`).
3. Results enter only by reading GitHub for a recorded installation; no route accepts a pushed result (`routes.ts`, `ci-routes.test.ts`).
4. The artifact is untrusted: size checked from `size_in_bytes` before download, a streaming byte cap during download, the download redirect followed without an `Authorization` header (`octokit.ts`), the inflated bytes counted while unzipping with a 1 MB cap (`parseArtifact`, fflate streaming `Unzip`, ignores zip-header sizes), `CiResultArtifact` bounds on every number.
5. A run attempt is stored once per installation, GitHub run id and attempt; a duplicate rolls back its `agent_runs` insert (`CiRepository.insertCiRun`).
6. CI `agent_runs` rows have `pr_id` null and `kind='review'`, so they never appear in a PR's run list, cost rollup or timeline. They do count in the agent card stats.
7. No `running` row is ever stored for a CI run.
8. The repo string is validated as `owner/name` and matched to an imported repo before any GitHub call.
9. Memory rows that look like a secret are never exported (`buildMemoryJsonl`); an edited workflow that looks like it holds a key is rejected unless `confirm_secret_warning` is sent (`exportCi`).
10. `modules/ci` imports no sibling module and no `reviewer-core` (`pnpm lint:arch`).

## Plan versus code

- `platform/container.ts` gains a `ciRepo` getter and override (the plan first said not to touch it). Routes may not import a repository, so the module cannot get its repository otherwise.
- `GitHubClient.listActionsSecretNames` also returns the optional `org_unreadable`, and `getRepoInfo` also returns the optional `private`.
- `CiPreview.memory.dropped` and `CiPreview.repo_public`, and `CiExportInput.confirm_secret_warning`, were added by the security fixes.
- `parseArtifact` uses streaming `Unzip` with a running counter, not `unzipSync` with an `originalSize` filter.
- Adapter tests live in `server/test/github-ci-adapter.test.ts`, not in `adapters.test.ts`.
